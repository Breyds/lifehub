# LifeHub — зміни

## 0.8.3 — Реальні тренування, ручні результати доріжки й про-розкидки

- **Тренування:** окремий інтерфейс для запису фактичних підходів, повторень, ваги й часу; галочкою підтверджуються тільки реально виконані сети. Підтримано готові плани та самостійний вибір вправ.
- **Мої відео:** імпорт MP4, WebM або MOV до 250 МБ у локальний захищений каталог користувача. Перегляд через системний відеоплеєр. Відео нікуди не надсилається, AI-аналіз не заявлено.
- **FitShow / доріжка:** проста ручна форма дати, хвилин, дистанції, середньої швидкості, нахилу, калорій, пульсу та кроків; кардіо-історія й сумарна дистанція. CSV-імпорт лишився необов’язковим. Прямої синхронізації FitShow немає.
- **CS2:** власна невелика редакційна підбірка перевірених за відкритими джерелами новинок із професійних демок (команди, гравці, турніри, мета і поради з практики); у застосунку є відразу без API. Онлайн-перевірка раз на 7 днів читає тільки нові **редакційно підготовлені** записи з нашого GitHub, а не скрапить nades.ai; відео та точний приціл залишаються за посиланням на першоджерело.
- **Безпека та сумісність:** старі записи LifeHub залишаються, дані вправ проходять серверну валідацію, місцеві відео не віддаються мережевим API.
- Повний аналіз техніки відео, прямий API FitShow й автоматичне ліцензоване отримання про-розкидок від сторонніх сайтів — майбутні функції.

## 0.8.2 — Fitness Studio + CS2 Utility Radar

- Фітнес: новий темний Fitness Studio, трикрокова анкета з фізичними параметрами, цілями, доступними днями, інвентарем та обмеженнями.
- 32 вправи з інструкціями та 8 оригінальних програм; розклад занять записується до наявного календаря LifeHub, виконання відмічається вручну.
- Журнал тренувань, кардіо, харчування, сканер фото страв із підтвердженням, AI-поради, щотижневі заміри та відстеження прогресу.
- FitShow: **прямої синхронізації немає**; підтримано ручний запис і імпорт простого сумісного CSV, коли доступний експорт.
- CS2: замість статичних прикладів CSNades — Utility Radar із новими роликами, URL і датами через YouTube Data API, позначення «не перевірено», збереження у власну бібліотеку. TikTok лише за ручними посиланнями; турнірні про-розкидки не підтверджуються автоматично.
- Збережено старі дані LifeHub, FACEIT, завдання, оновлення та інші розділи.
- Автоматична перевірка Windows: npm test, TypeScript/Vite build; графічний smoke-test Windows передано користувачу.
- Версія 0.8.2 — наступний крок LifeHub 0.8.x, а не повний реліз 1.0.0.

## 0.5.3 — ДТЕК, календар, фільтри, новини

- **«Світло»** тепер окрема вкладка. Введення адреси та її збереження відокремлено від мережевої перевірки.
- Старий прихований Electron-браузер для ДТЕК прибраний: він міг давати `ERR_ABORTED` і закривати вікно. Запит до неофіційного публічного `/ua/ajax` виконується з тайм-аутом і обробкою відмов.
- Графік у вигляді смуг на **сьогодні і завтра**; окремо «є світло», «немає», «можливо», «невідомо». Не вигадувати години, не трактувати відсутність даних як гарантоване світло.
- У календарі числовий бейдж показує кількість **важливих + критичних** завдань; у вікні дня є розкривні секції для важливих, критичних, повторюваних і звичайних.
- «Усі справи»: фільтри за типом завдання для всіх дат у списку.
- Новини: «Цікаво» вивчає тему й одразу прибирає картку; «Не цікаво» просто прибирає (технічний ID тимчасово зберігається, щоб стаття не з’явилася знову); «Зберегти» додає до окремої вкладки.
- Кнопка **«AI-банер»** створює явно позначену *ілюстрацію* на підставі заголовка через OpenAI Images API тільки після окремого підтвердження. Це **не фотографія фактичної події**. Не більше 3 ручних запитів на місяць у LifeHub; на сервері OpenAI встановлюй власні обмеження.
- Старі завдання й інтеграції Telegram/TikTok не видаляються.

### Перевірки

- Node unit tests: 74/74.
- TypeScript/TSX синтаксис: перевірено розбором TypeScript AST.
- Electron CJS: перевірено Node `--check`.
- **Ще не перевірено**: повний typecheck/Vite Windows build на справжніх npm-залежностях, отримання реального графіка ДТЕК під захистом сайту, OpenAI Images API. Спочатку перевірка CI на `main` і тільки потім тег.

### Безпека

- Адреса ДТЕК залишається у локальних налаштуваннях і відправляється лише ДТЕК під час твоєї перевірки.
- Не передавай API-ключі в чат чи GitHub. ZIP не містить твого профілю, токенів і завдань.
- Локальний індикатор бюджету $5 **не враховує точну ціну генерації зображень**: підтверджуй їх вручну та контролюй витрати в OpenAI Platform.


## 0.5.2 — Календар, фото новин, YouTube та ДТЕК

- Числовий бейдж у календарі лише для **критичних/термінових** справ; інші залишаються у вікні дня.
- У вікні дня окремі розділи: критичні, важливі, повторювані та звичайні.
- «Усі справи»: датовані групи зі вкладеною пріоритетністю й повторюваністю.
- YouTube Trend Radar: реальне посилання на відео й канал для результатів офіційного API; без API — чесні RSS-статті без вигаданих переглядів.
- Фото новин: спроба витягти оригінальне `og:image` для довірених сайтів, а потім зображення конкретно названої теми з Wikipedia з підписом.
- Графік ДТЕК: збереження адреси, запит на адресу через вбудований захищений браузер / `/ua/ajax`, розбір лише підтверджених часових слотів, показ результату всередині LifeHub та оновлення під час роботи. У разі блокування або неоднозначності дані не вигадуються.

### Перевірки

- Unit tests: 65/65.
- Syntax: Node Electron module check + TypeScript JSX transpilation.
- Не перевірено: робота DTEK на реальному сайті для твоєї адреси, TypeScript typecheck та Windows Electron EXE; ці кроки виконуємо через GitHub Actions і тест на ПК.

### Безпека

- Особиста адреса зберігається локально. У GitHub її не відправляємо.
- Секрети Telegram, AudD, YouTube, OpenAI не входять у вихідний архів та не повинні потрапляти в репозиторій.

## 0.5.4 — Прогрес, фотографії новин та резерв ДТЕК

- Лічильники: довільне введення десяткових значень (кома або крапка), швидкий крок 0,25 л, відображення понад план; точність до 0,001. Прогрес зберігається по днях.
- Дії редагування й видалення поруч із лічильниками більше не приховані до наведення курсора.
- Новини: прямий RSS Anime News Network і IGN, добір оригінальних зображень зі сторінок видавців, розпізнавання зображень з HTML-описів RSS, розширені назви аніме; кнопка повторного пошуку зображень для збереженої стрічки. Порожню тематичну плашку не можна гарантовано прибрати, якщо видавець не надає зображення.
- Світло: коли ДТЕК блокує AJAX і не дозволяє дізнатися чергу за адресою, користувач може один раз указати підтверджену чергу. LifeHub читає графік із публічного стороннього дзеркала (джерело і свіжість показуються). Без черги дані не вигадуються. Це **не заміна офіційної адресної перевірки**.
- Новий набір тестів для дробових значень, перевиконання, опублікованих графіків за чергою, старих даних та RSS-зображень.
