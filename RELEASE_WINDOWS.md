# LifeHub: як один раз встановити й потім автоматично оновлювати

## 1. Підготуй GitHub

Потрібен репозиторій GitHub, наприклад `YOUR_USERNAME/lifehub`. Для найпростішого автооновлення через стандартний GitHub provider репозиторій має бути **public**; приватний потребує окремого автентифікованого серверу або додаткового налаштування, і GitHub-токени не можна вбудовувати в програму.

- Створи порожній репозиторій на github.com.
- Завантаж туди файли цього проєкту **без** `node_modules`, `release`, `.env`, `lifehub.json` чи ключів API.
- Workflow `.github/workflows/windows-release.yml` уже є.
- У налаштуваннях репозиторію: **Settings → Actions → General → Workflow permissions**, якщо необхідно, дозволь запис `Read and write permissions` для GITHUB_TOKEN. У workflow вже задане `permissions: contents: write`.

Якщо працюєш через Git на Windows:

```powershell
git init
git add .
git commit -m "LifeHub 0.2.0"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/lifehub.git
git push -u origin main
```

Замінити `YOUR_USERNAME` на свій GitHub логін. Якщо репозиторій вже ініціалізований, `git init`/`git remote add` повторювати не треба.

## 2. Випусти першу версію

`package.json` зараз має версію **0.2.0**. Виконай:

```powershell
git tag v0.2.0
git push origin v0.2.0
```

GitHub Actions на **Windows runner** запустить `npm install`, `npm test`, збере Vite й інсталятор `electron-builder --win nsis`, замінить заглушку репозиторію на реальні owner/repo і опублікує GitHub Release із такими файлами:

- `LifeHub-Setup-0.2.0.exe`
- `latest.yml` (метадані для updater)
- `.blockmap` (для ефективнішого завантаження оновлень)

**Потрібно перевірити, чи збірка завершилась без помилок**. Перший Windows installer у поточному середовищі ще не перевірений. Якщо workflow зупиниться, відкрий вкладку **Actions** і подивися помилку — нічого не вважай випущеним, доки release не з’явився.

## 3. Установи на свій ПК

Відкрий GitHub → Releases → v0.2.0, завантаж `.exe` **один раз** і встанови. Непідписаний виконуваний файл може викликати SmartScreen; перевіряй, що це саме твій GitHub-репозиторій.

## 4. Коли ми доробимо нову функцію

Наприклад, для версії 0.2.1:

1. Внеси зміни в код (можемо зробити це разом у ChatGPT/Work).
2. Підвищ `"version"` у `package.json` до `0.2.1`.
3. Переконайся, що `npm test` та `npm run build` працюють.
4. Надішли зміни на GitHub і створи новий тег:

```powershell
git add .
git commit -m "LifeHub 0.2.1"
git push
git tag v0.2.1
git push origin v0.2.1
```

5. GitHub Actions створить новий публічний Release. **Встановлений LifeHub** перевірятиме оновлення після запуску та кожні 6 годин, якщо програма запущена; завантажить його і запропонує натиснути кнопку встановлення/перезапуску. Повторно шукати інсталятор не потрібно.

**Повідомлення в ChatGPT не редагує програму на твоєму комп’ютері автоматично.** Потрібна публікація змін у GitHub. Після налаштування репозиторію можна автоматизувати більшість цього процесу.

## 5. Безпека й майбутній реліз

- Не записуй API-ключ у source code, GitHub Issues, скриншоти та git коміти.
- Дані LifeHub лишаються локальними, поки немає окремої синхронізації.
- Для публічного релізу потрібні кодовий підпис (рекомендовано), перевірка доступності, тестування інсталятора та оновлень на Windows і політика конфіденційності.
- На першому етапі ми використовуємо GitHub Releases для особистого застосунку, а не власний платний сервер.
