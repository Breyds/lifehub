# Cloudflare Workers + D1 (Free)

Compatible with LifeHub 0.9.2. This is an optional single-user service. No Windows update is required. The Worker polls Telegram once per minute; responses and reminders may take a minute or longer. No public webhook is needed. Disable any other remote poller for the same bot. Existing local LifeHub polling stops after a successful cloud connection.

1. Create a Worker named lifehub-telegram on the Free plan and a D1 database lifehub-db. Bind the database to the Worker as DB.
2. Worker Settings → Variables and secrets: add three Secret values TELEGRAM_BOT_TOKEN (existing BotFather token), TELEGRAM_CHAT_ID (the linked chat shown in LifeHub), LIFEHUB_SYNC_KEY (random 32+ character secret, same value in LifeHub). Do not share these values or put them into code. Deploy the settings.
3. Open cloudflare-worker.mjs in this repository, click Raw, copy the entire file. In the Worker dashboard click Edit code, replace the default Hello World file with the complete JavaScript, and Deploy. No nodejs_compat flag or npm packages are needed. GET / should display a JSON object identifying LifeHub. This is a liveness check only, not authentication or synchronization.
4. Worker Settings → Trigger events → Add Cron Trigger: enter `* * * * *`. Save. Cloudflare can take several minutes to propagate Cron Trigger changes. The first authenticated health request initializes the private D1 table automatically; no manual SQL is required.
5. LifeHub → Settings → Notifications → Telegram 24/7: enter your HTTPS workers.dev origin and the exact LIFEHUB_SYNC_KEY. Click connect, consent to synchronization, verify last sync. Keep Telegram reminders enabled. Test /start, /today, a task completion, close LifeHub completely and test again; then reopen LifeHub and verify the mutation syncs back.
6. If disconnecting, sync first then use Disconnect server inside LifeHub; this stops cloud processing. Do not delete D1 before pending changes have synchronized. No need to change BotFather token unless it was exposed.

Limitations: polling latency, Free Worker CPU/D1 quotas, one state record capped at 1.5 MB, 1000 pending mutations, 40 queued outbound messages. Large calendars or bursts may require redesign, not paid upgrade by default. Outbox retries may duplicate a message after an interrupted send, but Telegram updates are deduplicated by update ID. The desktop wins conflicting edits under the existing sync protocol. Power schedules may be stale or unavailable; a known queue can use the existing public unconfirmed mirror. No home address or other API keys are synchronized. Deploy and live testing must be done in your Cloudflare account. Do not enable a paid plan for this setup.
