# LifeHub Telegram 24/7

Optional **single-user self-hosted** service. No server is provided automatically. It must run on an always-on machine or VPS with persistent storage and an HTTPS reverse proxy. Do not use GitHub Actions as a bot host. The Windows app retains its local database; the service keeps a limited task/schedule replica and a persistent mutation queue. The bot works from the last successful sync when the PC is off. PC changes require a sync; if both copies edit the same task, desktop changes win and the conflict is shown in settings.

1. Pair the existing bot in LifeHub, open Settings → Notifications, and copy the displayed chat ID. Use the existing token from BotFather, not a token posted in chat or source code. If necessary revoke the previous token and re-pair locally before connecting the server.
2. Set **server-side secret environment variables**: TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, LIFEHUB_SYNC_KEY (generate a random secret of at least 32 characters), PORT=8080, LIFEHUB_STATE_FILE=/data/telegram.json. Keep the data volume private and persistent, and back it up. Do not log Authorization headers or request bodies.
3. Build from repository root: `docker build -f server/Dockerfile -t lifehub-telegram .`. Run a single container using a private env file, a persistent volume mounted at /data, and a reverse proxy with HTTPS. The internal HTTP port must not be publicly exposed. Use a valid TLS certificate. Example: `docker run -d --restart unless-stopped --name lifehub-telegram --env-file /secure/lifehub.env -v lifehub-telegram-data:/data -p 127.0.0.1:8080:8080 lifehub-telegram`. Configure the HTTPS proxy separately.
4. Enter the HTTPS origin and sync secret in LifeHub settings; consent to sending task titles, notes (including workouts), completion/progress data and the power queue/schedule. The app validates the configured bot ID and chat. It does not send the bot token, home address, or unrelated API credentials to the sync endpoint. Local Telegram polling is suspended while the cloud configuration is active. The server starts polling only after a successful sync. Wait for the first confirmed sync and test /start, /today and a task update, then close LifeHub and test again.
5. The cloud service uses Europe/Kyiv time, sends scheduled task reminders and evening recap, and uses the synced power schedule or the existing public DTEK mirror for a known queue. Mirror results are explicitly unconfirmed; no address lookup is performed on the server. It does not reproduce every desktop background notification (e.g. CS2/music). If the PC is off, new desktop data cannot be synchronized. Do not run two cloud instances or another Telegram poller for the same bot.
6. To return to local mode, disconnect the cloud server in LifeHub while online; the app syncs pending changes and deactivates remote polling before resuming local polling. The server retains its local copy until you remove its private volume; deleting that volume loses pending unsynced changes.

Deployment, live Telegram delivery, and Windows end-to-end sync must be verified with a real hosted instance. Unit tests exercise the mutation merge and local menu without real credentials.
